# Obsidian 知识库整理 Skill

> 给 Agent 看的入口。用户把这个 Skill 交给你（任意能读 `.md` 的 Agent，如 WorkBuddy / Claude / Copilot），你就能帮他把 Obsidian vault 整理成「人和 Agent 都能用」的结构化知识库，并持续迭代维护。
> 核心理念：**人和 Agent 一起用**——用户放东西、找东西有规矩；Agent 读库、写库有地图、有进度、有索引，两边不打架。

---

## 这个 Skill 能做什么

- 从零搭一个新知识库（定母题 → 收原料 → 找维度 → 搭骨架 → 归位 → 抽底座 → 留生长口）
- **接手一个已有的乱库**：先只读摸底、出归类提案（每个动作带理由），用户点头后一批一批整理，笔记内容零改动
- 日常整理：新东西入库、查重归位、写一句话头、旧版升级走口子
- 定期体检：断链 / 孤儿页 / 过时内容三连扫描
- 跨会话 / 换 Agent 接手：用「热缓存 hot.md」保留进度上下文
- 让 Agent 基于知识库答题、写稿、整理（三档接入：直接读 → MCP → RAG）

## 什么时候触发

用户说「整理 / 搭 / 理顺我的知识库 / 笔记」「帮我归档」「基于我的库写点东西」「换了个 Agent 接上之前的进度」等。

## 核心原则（贯穿所有动作，不能违背）

1. **库是资产不是记忆**：不主动做「定期打扫」。只在用户要求，或判断某条很重要时才动；入库时摆对位，平时不用管。
2. **人和 Agent 都能用**：结构既要让人点目录能找到，也要让 Agent 顺着 `00_目录` 逐层读到。
3. **结论与证据分开**：用户的判断 / 结论，和别人的资料（竞品、拆解、他人方法）**分开放**，各长各的。结论会被推翻、会反复改；资料是素材、只增不改。混放会互相误伤。
4. **不删东西**：结论升级 / 内容换版时，旧内容剪切进 `_旧版/{项目}/`，原处新内容正下方写一行 `⤵ 旧版跳转`；内容重复被合并时，旧处写一行 `⛔ 已被 [[新笔记]] 取代（日期）`。**升级用 ⤵，重复用 ⛔，两种标记别混用**（体检要靠它们收网，标错就断）。本体永远不删。
5. **先轻后重**：小库用最轻方案（直接读 + 分层目录 + 一句话头），长大再叠重方案（MCP / RAG）。别一上来就搭复杂系统。
6. **够杂了才拆**：同一文件夹平铺超过 8 个文件、展开要滚动，才建子文件夹。不为整齐硬造空结构。

## 工作流

**先对场景入座**（别通读全包再拼步骤）：

| 用户的情况 | 走哪条 |
|---|---|
| 已有一个库（乱 / 没结构），要整理 | A 接入 → **B0 接手摸底** → 按需归位 |
| 要从零建个新库 | A 接入 → B |
| 平时加东西 / 归档 | A（做过就跳）→ C |
| 结论变了要更新 | D |
| 换会话 / 换 Agent 接进度 | E |
| 基于库答题 / 写稿 | A → `references/Agent接入三档.md` 三档 |

### A. 接入：先放地图（第一步永远做）
库根放一份 `AGENTS.md`（见 `assets/AGENTS.md`，可直接复制改成你的库结构）。作用：写给 Agent 看的结构地图 + 纪律，让 Agent 不迷路、不乱翻、知道哪些碰不得。零成本、立刻生效。
细节见 `references/Agent接入三档.md`。

### B. 从零搭库（用户要建新库）
照 `references/搭库七步.md`：定母题 → 收原料（允许乱）→ 找分类维度（正交、互斥穷尽）→ 搭空骨架 → 归位（放不进=维度错，回改）→ 抽底座（跨分类的通用规律单独一层）→ 留生长口（新规则只管新增、作废写取代链）。

### B0. 接手已有库（库已存在、要整理——最常见场景）
**原则：先摸底、后动手；小步归位，不搞大迁移**（移动必断引用，尤其反引号里手写的路径会静默断）。

**三条红线（每一步都要守住）：**
- **分类从库里的实际内容判断，不套任何现成模板**——用户的库是什么主题就按什么分类；用户不用自己想好分类，你提案、他点头。
- **只动位置，不碰内容**——只做移动文件、建文件夹、写目录页；笔记里的字一个不改、一个不删。
- **分批执行，一批一确认**——绝不一次全库重排；每批结束交改动清单，用户说继续才动下一批。

1. **摸底（只读，零改动）**：跑一遍库体检三连（动作五）+ 读根目录现状，向用户报告：库里有什么、多少篇、多乱、问题在哪（要有数字，不说「我觉得挺乱」这种空话）。
2. **放地图**：`assets/AGENTS.md` 复制到库根，按这个库的真实结构改好。
3. **出归类提案**：基于摸底结果给提案表——保留 / 合并 / 拆分 / 新建 / 归位，**每个动作都带「为什么」**，用户看理由拍板；用户改哪条照哪条办，库是他的。
4. **归位**：按提案一次一批地动，**搬前搬后各跑一次 check_links.py**；每批结束交改动清单（动了哪些文件、笔记内容改动数 = 0）；拿不准的列清单问用户，不擅自大迁移。
5. **补一句话头**：给没写 `> 一句话：` 的篇目补写（可以让 AI 批量起草、用户过目）。
6. **收尾**：跑 `scripts/gen_index.py` 生成各级 `00_目录`，写第一份 `hot.md`，最后再跑一次体检确认没搬断东西。

### C. 日常整理（用户加东西 / 要归档）
照 `references/日常整理五动作.md`：
- **动作一 三问定性**：我的判断/实操/踩坑/结论 → 对应主题夹；别人的资料 → 资料区（和自己的分开）；纯刷到的 → 别塞。
- **动作二 三步查重**：读根 `00_总目录` → 读目标层 `00_目录` → 有同样的改原篇、不新建；没有才新建（第一行写一句话头）。入库后跑一次 `scripts/gen_index.py`（见 `scripts/README.md`）自动刷新各级 `00_目录`，不用手改（脚本只覆盖它自己生成的带标记文件；用户手写的目录不会被覆盖）。
- **动作三 一句话头**：每篇标题下第一行写 `> 一句话：{讲什么}——{什么时候看}`。这是全库和 AI 协作的命根子（AI 靠它决定要不要打开这篇）。
- **动作四 旧版口子**：结论升级时，旧内容剪切进 `_旧版/{项目}/{原笔记名}_旧版_{日期}.md`，原处写新内容，正下方写一行 `⤵ 旧版跳转`（指向刚挪进去的旧版文件）。重复被合并时才用 `⛔ 已被 [[新笔记]] 取代` 标记。
- **动作五 库体检三连**（三件事三个来源，别漏）：
  - ① **断链** → 跑 `scripts/check_links.py`（双链 / 路径 / 附件 / 反引号四类指向不存在目标的引用）
  - ② **旧版 / 重复 / 散文件** → 跑 `scripts/scan_old.py`（孤儿页线索也在它输出里：顶层散文件、极短文件；正式判定再比对各级 `00_目录`——没进任何目录、也没被任何链接指向的，就是孤儿页）
  - ③ **过时** → 自己 grep 库里的 `⛔ 已被 [[新笔记]] 取代` 标记，列出还在被引用的旧版
  搬完文件必跑，平时一月一次。脚本用法见 `scripts/README.md`。

### D. 迭代升级
用户改了想法 / 结论 → 走动作四旧版口子。新规则只作用于新内容，存量不批量迁移（移动必断引用，代价大于收益）。

### E. 热缓存：跨会话 / 换 Agent 接手
每次会话结尾，把「当前在推进什么、干到哪一步、有没有结论刚变、上轮关键要点」写进库根 `hot.md`（**500 字以内，覆盖式更新，只留最新状态**）。
下次开新对话（哪怕换了另一个 Agent），先读 `hot.md` + `00_总目录` 两份就能接上进度，不用重读全库、不用用户重新交代背景。
指令可直接用：`读完这轮对话，把要点更新进库根 hot.md，500 字以内；只留最新状态，旧状态直接覆盖。`
细节见 `references/Agent接入三档.md` § 热缓存。

## 结构规范（人和 Agent 共读）

- 每层放一份 `00_目录.md`，**只列本层直接子项**（子文件夹一行带过、点进去看它自己的目录，绝不平铺孙辈）。模板见 `assets/00_目录模板.md`；库大了直接跑 `scripts/gen_index.py` 自动生成，不用手搓（**首次建议直接跑脚本生成**——自带「脚本生成」标记、以后每次重跑自动刷新；手写的目录脚本不会覆盖，但也就不会自动更新）。
- 每篇第一行 `> 一句话：讲什么 + 什么时候看`。
- 移动文件必跑库体检：反引号里手写的路径（`../xx/yy.md`）Obsidian 不会自动更新，会**静默断链**——肉眼看不出，只有扫一遍才暴露。

## 给 Agent 的纪律

- 回答用户前先搜 vault 再答，不凭自己记忆补全。
- 改文件前先读、用增量 Edit，不整篇重写。
- 不动用户个人文件夹（Desktop / Downloads 等）除非被明确要求。
- RAG 场景写死检索纪律：「只用 vault 上下文回答，不够就直说，别用训练知识补全」，防幻觉。
