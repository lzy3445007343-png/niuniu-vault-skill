# 结构规范：分层目录 + 目录页 + 一句话头

> 这一层回答：库怎么摆，让你自己找文件不费劲，AI 也能顺着目录一层层找到。

## 一、核心思路：每一层只管自己这一层

每个文件夹放一份 `00_目录.md`，它**只列本层的直接子项**，绝不往下平铺。

- **人**：点进任何一层，第一眼就是「这层有什么、各自干嘛」，顺着点进去一层层钻——永远不用在几十个文件里翻。
- **AI**：目录页就是 AI 的地图——先读 `00_目录.md` 就知道该进哪个文件夹、读哪个文件，不用全库瞎翻。

⚠️ 最容易犯的错：把整个库平铺成一张大目录。文件多了平铺跟没整理一样——**一层只看一层，才不会淹**。

## 二、00_目录页怎么写（照 `assets/00_目录模板.md` 抄）

每个 `00_目录.md` 两部分：**子文件夹 + 本层文件**，每个条目都写清「是什么、什么时候用」。

三条纪律：
1. **只列直接子项**——子文件夹一行带过（名字 + 干嘛的 + 篇数），点进去看它自己的 00_目录，绝不列孙辈。
2. **索引放第一节**——打开目录第一眼是目录不是前言。要的是找文件不是读背景。
3. **每个条目带一句「什么时候用」**——给未来的你和 AI：需要的那一刻才找得到。

## 三、每篇笔记第一行：`> 一句话：…`

```markdown
# 笔记标题
> 一句话：这篇讲什么 + 什么时候看（30-60 字）
```

例：
```markdown
# 变现渠道地图
> 一句话：把同一份内容铺到公众号、小红书、私域等不互相依赖的渠道——担心一条渠道倒掉时看这篇。
```

**为什么对 AI 最关键**：AI 判断「该不该读这篇」靠这一行。没有它，AI 只能打开全文——库一大读不动；有了它，扫一遍每篇的一句话就能精准定位。
**为什么对你也关键**：写明「什么时候用」，库大了才不会攒一堆「以后没打开过」的文件。

进阶（库过 50 篇再上）：每篇加 frontmatter（YAML 头），把一句话写进 `summary` 字段，配合 Dataview 出动态表格——先轻后重。

## 四、文件夹 / 标签 / frontmatter：社区三件套（进阶）

上面「分层目录」本质就是最简单的 **MOC**（内容地图）做法。库长大后再补三样：
- **文件夹**：只按「你在做什么事」分，别超两层深。
- **标签**：是便利贴不是格子——横切检索用，每篇 2-5 个，别当主骨架。
- **frontmatter**：库过 50 篇再统一加（title / tags / created / status / summary），全库字段名一致是底线。

⚠️ 别为了整齐硬造结构：内容还不够多就平铺放着，「够杂了才拆」。

## 五、移动文件 = 必断引用（⚠️ 最容易翻车）

| 写法 | 挪动后 |
|---|---|
| `[文字](路径.md)` 可点链接、`[[双链]]` | 在认这两套语法的软件里挪，会自动更新 |
| 反引号里手写的路径（`` `../xx/yy.md` ``） | **不会自动更新，静默断掉，肉眼看不出** |

两条保命规矩：
1. 层内跳转优先用 `[[双链]]` 或可点链接，少写死路径。
2. 挪完文件夹，说一句：「帮我扫一遍这个库，列出所有断掉的链接」——搬前搬后各扫一次，新增断链当场修。

## 诚实标注
「分层目录 + 一句话头」是实战库跑出来的；三件套 / PARA / frontmatter 是社区共识。两套不冲突，先轻后重。目录页有维护成本，更省事的做法是对 AI 说：「按 00_目录 的格式，帮我更新这一层的目录页」。
